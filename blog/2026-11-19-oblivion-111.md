This release is all about optimization. A hundred players in one area used to give you 2 to 3 FPS. That is 20 to 25 now, and 40 to 50 with frame generation turned on, which we consider a massive improvement given how the game is coded. Even the busiest hub areas and MMO-style servers are now possible.

Other players' characters no longer share the game's animation budget, which left some of them stuttering while others moved smoothly. All of them now animate and move smoothly, whatever frame rate and ping they are playing at. The rest of the release is bug fixes.

<!-- truncate -->

## Animation

In a crowd the game used to animate some of the players on screen every frame and the rest every second or third, so some of them stuttered. Other players' characters are animated every frame now, however many of them are in view.

Their animations also keep running while they are off screen, so a character is in the right pose when you turn back to it. NPC crowds are unchanged.

## Fixed

### In the game

- Fixed some objects, plants among them, never being synchronized at all, so players saw them in different states.
- Fixed other players counting as standing higher than they really were, which broke scripts such as pressure plates.
- Fixed some game objects being pulled into the player's cell when they should have stayed where they were.
- Fixed weapon perk effects hitting whoever stood in front of the attacker instead of the actual target.
- Fixed Marksman perk effects working for only one player.
- Fixed a Hand to Hand disarm duplicating the weapon.

### SDK

- `KeyboardEvent.code` is populated in CEF pages, the in-game browser UI that a mod draws its interface in. Key events reached CEF without a scan code, so a page saw the right `key` and `keyCode` and an empty `code`.
- `PlayerActivity.InDialogue` is true only while the player is in dialogue. It read the game's conversation package before, which is also set while NPCs within earshot talk to each other, so two NPCs chatting nearby made the player look like they were in dialogue. Barter and persuasion started from a conversation still count as dialogue.

## Updating

The server and the game mod ship as `1.1.1`, and the SDK packages stay at `1.1.0`.

* **Servers.** Downloads for Windows and Linux are on the [Installation](/oblivion-mp/docs/Server/installation) page. Copy the `saves`, `data` and `branding` folders, `config.json` and your own mods into the new package, as in [1.1.0](/releases/oblivionmp-sdk-110#upgrading). Until a server updates, its players stay on `1.1.0`.
* **Players.** Nothing to do. A player's install has to match the server's version, and the launcher sorts that out before it connects you.
* **Mods.** Nothing to do. The SDK packages have not changed, so a mod built against `1.1.0` keeps working without recompiling. The two fixes above reach it from the server and the game mod rather than from the packages.

Check [Known issues](/oblivion-mp/docs/known-issues) before reporting a bug. Anything not on it, report on the [OblivionMP Discord](https://discord.gg/obmp).
