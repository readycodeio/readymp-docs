`1.1.0` is out. The headline is a new Networked Events API: a mod says something happened, and every other mod, on either side, gets a say before it takes effect. The SDK itself got smaller too: it loads fewer assemblies, keeps the attributes a mod writes against in one place, and its namespaces now match the mod's name, `OblivionMP.SDK`.

Mod authors: this release has breaking changes. Read [Upgrading](/releases/oblivionmp-sdk-110#upgrading) before you rebuild.

## Networked events

An RPC is one message with one handler on each side. A networked event is a struct describing one thing that happened, a wave, a spell cast, an item changing hands, and it goes through stages: a mod raises it, the server checks it, and it reaches the players who should hear about it. Along the way any mod can refuse it, change it, act on it or just watch it, including mods that did not declare it.

* **Who hears it** is set by the event's scope: a cell, an area, the server, everyone.
* **Who may raise it** is set by its policy, for example only the game that owns the subject.
* **Clients can guess at the result.** Mark a value `[Predictable]` and the client shows the change at once, then takes it back if the server refuses.
* **The game raises its own events** through the same API: health changes, item transfers, time and weather, spell casts, sitting down and getting up, eating and drinking. A mod can handle or refuse any of them.

[Networked events](/oblivion-mp/docs/Modding/Concepts/networked-events) in the docs covers declaring, raising and handling them.

## Fewer assemblies

Several small assemblies are folded into the ones they always shipped with. A mod sees this only in the namespaces it imports, listed under [Upgrading](#upgrading):

* `Yooni.Native.Logging`, `.LowLevel`, `.Container` and `.Serialization` are one assembly, `ReadyM.Native`.
* `ReadyM.Api.Multiplayer` is part of `ReadyM.Api`. Its namespaces did not change.
* `ReadyM.SDK.Chunks` is part of `ReadyM.SDK`, and `ReadyM.Relay.Client` part of `ReadyM.SDK.Client`.

## Upgrading {#upgrading}

* **Bump the SDK packages to `1.1.0`.**
* **Rename `OblivionMp.Sdk` to `OblivionMP.SDK`.** It covers `OblivionMP.SDK.Common` and `OblivionMP.SDK.Serverside` too. C# names are case-sensitive, so a case-sensitive find and replace of `OblivionMp.Sdk` with `OblivionMP.SDK` across your sources is the whole change.
* **Rename `Yooni.Native` to `ReadyM.Native`.** `NativeList<T>`, `NativeString64` and the rest keep their names; only the namespace changes, for example `using Yooni.Native.Container;` becomes `using ReadyM.Native.Container;`.
* **RPC attributes moved to `ReadyM.SDK.Attributes`.** `[ClientToServer]`, `[ServerToClient]`, `[ClientToClients]` and `RelayMode` live next to `[RpcContracts]` now, so a contracts file that already imports `ReadyM.SDK.Attributes` for `[RpcContracts]` needs no change. The `ReadyM.Api.Multiplayer` imports it used for them can go.
* **`IServerEvents` moved to `ReadyM.SDK.Server.Events` and hands out shapes.** Update your handlers:

  | `1.0.0` | `1.1.0` |
  |---|---|
  | `OnPlayerConnected(PlayerId, Entity)` | `OnPlayerConnected(Player, Guid)`, with the player's ReadyM id |
  | `OnPlayerDisconnected(PlayerId, Entity, DisconnectReason)` | `OnPlayerDisconnected(Player, Guid, DisconnectReason)` |
  | `OnAreaCreated(AreaId, Entity)`, `OnAreaDeleted(AreaId, Entity)` | `OnAreaCreated(Area)`, `OnAreaDeleted(Area)` |
  | `OnCellCreated(AreaId, CellId, Entity)`, `OnCellDeleted(AreaId, CellId, Entity)` | `OnCellCreated(Cell)`, `OnCellDeleted(Cell)` |
  | `OnPlayerActivatedCell(PlayerId, AreaId, CellId)`, `OnPlayerDeactivatedCell(PlayerId, AreaId, CellId)` | `OnPlayerActivatedCell(PlayerId, FullCellId)`, `OnPlayerDeactivatedCell(PlayerId, FullCellId)` |
  | `OnWorldEntityCreated(Entity)` | `OnWorldCreated(World)` |

  `OnPlayerJoinedArea` and `OnPlayerLeftArea` are unchanged.
* **The connection events on `IPlayers` are gone.** They were marked obsolete in `1.0.0`; use `IServerEvents.OnPlayerConnected` and `OnPlayerDisconnected`.
* **Recompile.** The generated code changed with the SDK, so a mod built against `1.0.0` does not load on `1.1.0`, even if none of the above applies to it.
