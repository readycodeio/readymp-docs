`1.1.0` is out, and the big one is networked events: a way for mods to tell each other that something happened, and to step in before it takes effect. We also used this release to clean up the SDK. It ships fewer assemblies, and its namespaces now match the mod's name, `OblivionMP.SDK`.

That cleanup breaks existing mods, so read [Upgrading](/releases/oblivionmp-sdk-110#upgrading) before you rebuild.

## Networked events

RPCs stay. When a mod only talks to its own other half, they are still the simplest thing that works. The catch is that nobody else is in the loop. Other mods cannot see an RPC or stop it, and the player waits on the server before anything changes on screen.

A networked event is a struct describing one thing that happened, like a spell cast or an item changing hands. The mod raises it, the server checks it, and then it goes out to the players who should hear about it. Any mod can hook in along the way, even one that did not declare the event.

A hook can refuse the event: a safe-zone mod can block damage inside a town without knowing which combat mod dealt it. It can change the event before it lands, say halving that damage instead. Or it can just watch, which covers logging and achievements without touching anyone else's code.

The waiting goes away too. Mark a value `[Predictable]` and the client shows the change right away, then rolls it back if the server says no.

Each event has a scope, which decides who hears it (a cell, an area, the server or everyone), and a policy, which decides who may raise it. The game raises its own events through the same API, for health, items changing hands, time and weather, spell casts, furniture and food, so your mod can hook into those as well.

Our rule of thumb: if only your own mod cares, send an RPC. If other mods might want a say, or the player should not wait on the server, raise a networked event. The [Networked events](/oblivion-mp/docs/Modding/Concepts/networked-events) page shows how to declare, raise and handle them.

## Fewer assemblies

We folded a handful of small assemblies into the ones they always shipped with. Your mod only notices the namespaces it imports, and [Upgrading](#upgrading) covers those.

* The four `Yooni.Native` assemblies (`Logging`, `LowLevel`, `Container`, `Serialization`) are now one, `ReadyM.Native`.
* `ReadyM.Api.Multiplayer` is part of `ReadyM.Api`, with the same namespaces as before.
* `ReadyM.SDK.Chunks` is part of `ReadyM.SDK`, and `ReadyM.Relay.Client` is part of `ReadyM.SDK.Client`.

## Upgrading {#upgrading}

* **Bump the SDK packages to `1.1.0`.**
* **Rename `OblivionMp.Sdk` to `OblivionMP.SDK`**, which includes `OblivionMP.SDK.Common` and `OblivionMP.SDK.Serverside`. C# names are case-sensitive, so make it a case-sensitive find and replace across your sources. Nothing else changes.
* **Rename `Yooni.Native` to `ReadyM.Native`.** Only the namespace moved. `NativeList<T>` and `NativeString64` keep their names, so `using Yooni.Native.Container;` just becomes `using ReadyM.Native.Container;`.
* **The RPC attributes moved to `ReadyM.SDK.Attributes`.** `[ClientToServer]`, `[ServerToClient]`, `[ClientToClients]` and `RelayMode` now sit next to `[RpcContracts]`. Your contracts file already imports that namespace for `[RpcContracts]`, so it builds as is, and you can drop the `ReadyM.Api.Multiplayer` imports it needed before.
* **`IServerEvents` moved to `ReadyM.SDK.Server.Events`, and its handlers get shapes instead of ids and raw entities.** Update their signatures:

  | `1.0.0` | `1.1.0` |
  |---|---|
  | `OnPlayerConnected(PlayerId, Entity)` | `OnPlayerConnected(Player, Guid)`, with the player's ReadyM id |
  | `OnPlayerDisconnected(PlayerId, Entity, DisconnectReason)` | `OnPlayerDisconnected(Player, Guid, DisconnectReason)` |
  | `OnAreaCreated(AreaId, Entity)`, `OnAreaDeleted(AreaId, Entity)` | `OnAreaCreated(Area)`, `OnAreaDeleted(Area)` |
  | `OnCellCreated(AreaId, CellId, Entity)`, `OnCellDeleted(AreaId, CellId, Entity)` | `OnCellCreated(Cell)`, `OnCellDeleted(Cell)` |
  | `OnPlayerActivatedCell(PlayerId, AreaId, CellId)`, `OnPlayerDeactivatedCell(PlayerId, AreaId, CellId)` | `OnPlayerActivatedCell(PlayerId, FullCellId)`, `OnPlayerDeactivatedCell(PlayerId, FullCellId)` |
  | `OnWorldEntityCreated(Entity)` | `OnWorldCreated(World)` |

  `OnPlayerJoinedArea` and `OnPlayerLeftArea` are unchanged.
* **The connection events on `IPlayers` are gone.** They were already obsolete in `1.0.0`. Use `IServerEvents.OnPlayerConnected` and `OnPlayerDisconnected` instead.
* **Recompile.** The generated code changed with the SDK, so a mod built against `1.0.0` will not load on `1.1.0`, even if nothing above applies to it.
