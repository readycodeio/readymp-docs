`0.3.1` 修复了大家反馈最多的两个资源问题，内存和 CPU，同时修掉了一处会卡住进度的问题和一批重连相关的 bug。二进制软件包和 Docker 镜像都已经发布。

模组作者请注意：本版本有一处小的破坏性变更，详见下文的“升级”一节。

<!-- truncate -->

## 修复

* **内存占用过高。** 服务器不会再像 `0.3.0` 那样持续增长内存占用。
* **Linux 上 CPU 占用过高。** 同样的游戏会话，Linux 主机的 CPU 消耗此前远高于 Windows 主机。已修复。
* **Bullguard 战斗的过场动画不触发**，这会让战役在该处卡住无法推进。现在过场动画会正常触发。
* **重连相关的 bug。** 玩家在游戏进行中重连时出现的一系列问题已修复。

## 已知问题

我们把这些如实列出来，因为其中两个会影响正常的战役流程：

* **敌人可能变为不可见。** 当玩家之间拉开足够大的距离时，某些敌人会对一名或多名玩家停止渲染。
* **重连可能让隐藏的植物敌人出错。** 重连之后，无论是使用 `reconnect` 命令还是因为掉线，隐藏的植物敌人都可能以植物形态进行战斗。
* **Boss 可能对某些玩家瞬间死亡。** 战斗刚开始 Boss 就倒下，而且只发生在会话中的部分玩家身上。

这三个问题我们都还在排查，会在后续版本中修复。

## 升级 {#upgrading}

`0.3.1` 带有一处小的破坏性变更。核心组件上的 `string` 字段现在改为 `NativeString256`（来自 `Yooni.Native.Container`）：

| 组件 | 字段 |
| --- | --- |
| `NicknameComponent` | `Nickname` |
| `PlayerComponent` | `Nickname` |
| `TamerComponent` | `Guid`、`UnitPath` |

读写其中任何一个字段的模组都需要针对 `0.3.1` 重新编译，并且在以前直接拿到 `string` 的地方通常要加上 `.ToString()`：

```csharp
// 0.3.0
var guid = tamer.Guid;

// 0.3.1
var guid = tamer.Guid.ToString();
```

这些组件位于 `ReadyM.Wukong.Common` 中，模组的两半都会引用它，所以这一变更同时影响使用这些字段的客户端模组和服务器端模组。除此之外没有别的改动，因此大多数模组重新编译一次就够了。

如果你是从 `0.2.4` 升级过来，在此之上，[`0.3.0` 的迁移指南](/releases/wukongmp-sdk-030#migration-guide)依然完全适用。

文档已经就地更新，因此[安装指南](/wukong-mp/docs/Server/installation)和[快速开始](/wukong-mp/docs/quick-start)现在描述的是 `0.3.1`。
